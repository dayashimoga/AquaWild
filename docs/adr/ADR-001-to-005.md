# Architecture Decision Records (ADRs 001–005)

## ADR-001: Universal Cross-Platform Framework & Rendering Engine
- **Status**: Accepted
- **Date**: 2026-11-22
- **Owners**: `solution-architect`, `mobile-agent`, `desktop-web-agent`
- **Context**: We must deliver a single, high-performance codebase targeting Android, iOS, Web, Windows, macOS, and Linux across phones, tablets, laptops, and desktops at 60/120 FPS.
- **Decision**: Use **Flutter (Stable 3.38+ / Dart 3.10+)** with **Material 3**, **Flutter Impeller / CustomPainter hardware-accelerated canvas**, **Riverpod** for reactive state management, and **GoRouter** for declarative deep-linkable navigation. Avoid any direct `dart:io` imports in UI/domain layers so Flutter Web and desktop targets compile from identical sources.
- **Consequences**: Unified rendering pipeline across all 6 platforms; deterministic 60/120 FPS fluid animations; zero platform fragmentation.

## ADR-002: Real-Time Fluid Simulation & SVG Red Panda Pool Rendering Architecture
- **Status**: Accepted
- **Date**: 2026-11-22
- **Owners**: `animation-agent`, `ux-ui-agent`
- **Context**: Existing hydration apps use static flat masks. We need realistic wave physics, multi-drink stratified layers inside exotic animal silhouettes, and a top-down floating SVG Red Panda launch screen that runs at 60/120 FPS on mobile, web, and desktop while respecting reduced-motion accessibility.
- **Decision**:
  1. Implement a hardware-accelerated 1D/2D coupled spring-damper shallow-water solver (`FluidWaveSolver`) paired with a multi-stratum `CustomPainter` + optional GLSL fragment shader pipeline (`shaders/water_pool.frag`).
  2. Render exotic animals and the floating Red Panda using high-precision vector paths and layered SVG components so they scale crisply to 4K/Retina displays with independent limb/tail/sunglasses/ripple transformations.
  3. Automatically pause continuous wave tickers when `reducedMotion` is enabled or when the window/tab is backgrounded.
- **Consequences**: Zero-jank 120Hz fluid physics on all 6 platforms, deterministic testability of wave math in unit tests, and 100% WCAG 2.2 motion-safety compliance.

## ADR-003: Offline-First State Persistence & Supabase Cloud Synchronization
- **Status**: Accepted
- **Date**: 2026-11-22
- **Owners**: `backend-agent`, `solution-architect`, `security-agent`
- **Context**: Users log drinks frequently in offline or low-connectivity environments (gyms, flights, trails), yet require real-time multi-device cloud backup and analytics via Supabase PostgreSQL.
- **Decision**: Adopt an **Offline-First Optimistic Repository Pattern**. Every drink entry, animal evolution, and streak update writes immediately to local storage (`SharedPreferences` / local JSON store) and appends an idempotent mutation event to an offline sync outbox queue. When Supabase credentials are provided and connectivity is available, `SupabaseSyncService` flushes the outbox to PostgreSQL protected by strict Row-Level Security (`auth.uid() = user_id`) and subscribes to Supabase Realtime changes.
- **Consequences**: Instant 0ms UI latency on drink entry, zero data loss offline, and enterprise multi-tenant security in cloud mode.

## ADR-004: OpenAI-Compatible AI Hydration Architecture with Deterministic Physiological Fallback
- **Status**: Accepted
- **Date**: 2026-11-22
- **Owners**: `backend-agent`, `product-agent`, `security-agent`
- **Context**: The app must provide intelligent, context-aware AI hydration recommendations using an OpenAI-compatible architecture without breaking if the user is offline or has not yet configured an external API key.
- **Decision**: Implement `AiHydrationService` adhering to the OpenAI `/v1/chat/completions` JSON schema (supporting custom base URLs, model selection, and Supabase Edge Function proxying) with strict input sanitization and system-prompt guardrails. Pair it with an embedded **Physiological Hydration Heuristic Engine** that computes real-time hydration gap analysis, caffeine diuretic offset, electrolyte balance, and weather/workout adjustments locally with zero latency.
- **Consequences**: Works out-of-the-box in every environment (offline, CI tests, and live LLM cloud deployments) while preventing prompt injection and exposing zero secrets in client bundles.

## ADR-005: Multi-Platform GitHub Actions CI/CD Matrix & Selective Build Governance
- **Status**: Accepted
- **Date**: 2026-11-22
- **Owners**: `release-devops-agent`, `qa-agent`, `security-agent`
- **Context**: The repository must support automated builds for Android, iOS, Web, Windows, macOS, and Linux, individual platform workflows, and a master workflow allowing manual selection of target platforms and uploading all generated artifacts.
- **Decision**:
  1. Establish Git Flow branch strategy (`main`, `develop`, `feature/*`, `release/*`, `hotfix/*`).
  2. Create dedicated per-platform workflows (`android.yml`, `ios.yml`, `web.yml`, `windows.yml`, `macos.yml`, `linux.yml`) plus a master orchestrator (`build-all.yml`) triggered via `push`, `pull_request`, `schedule`, and `workflow_dispatch` with boolean platform toggles and quality/security gate prerequisites.
- **Consequences**: Predictable, auditable builds for all 6 operating systems with selective platform cost control and automated artifact retention.
